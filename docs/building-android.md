# Building the Android release (.aab)

This builds a signed Android App Bundle (`.aab`) for upload to the Google Play Console.

## One-time setup

1. **Keystore:** place the upload keystore at `android/app/keystore.jks`.
   It is git-ignored (`*.jks`, and the whole `android/` folder).

2. **Passwords:** add these to `android/gradle.properties` (git-ignored):

   ```
   MYAPP_UPLOAD_STORE_FILE=keystore.jks
   MYAPP_UPLOAD_KEY_ALIAS=your-key-alias
   MYAPP_UPLOAD_STORE_PASSWORD=your-store-password
   MYAPP_UPLOAD_KEY_PASSWORD=your-key-password
   ```

3. **Backup:** keep a copy of `keystore.jks` and the passwords somewhere safe, outside this project.
   If you lose the upload key, you cannot update the app on Google Play.

## Release signing in `android/app/build.gradle`

`build.gradle` is generated by `expo prebuild`, so this change must be made again after every prebuild.

1. Inside `signingConfigs { ... }`, after the `debug { ... }` block, add:

   ```groovy
   release {
       storeFile file(MYAPP_UPLOAD_STORE_FILE)
       storePassword MYAPP_UPLOAD_STORE_PASSWORD
       keyAlias MYAPP_UPLOAD_KEY_ALIAS
       keyPassword MYAPP_UPLOAD_KEY_PASSWORD
   }
   ```

2. In `buildTypes { release { ... } }`, change the signing line from the debug key to the release key:

   ```groovy
   signingConfig signingConfigs.release
   ```

   It was `signingConfig signingConfigs.debug`.

Without this, the release build is signed with the debug key, and the Play Store will reject it.

## Build

1. Bump the version in `app.json`: `version` (for example `1.2.2`) and `android.versionCode` (must be higher than the last upload).
2. Regenerate the native folder so `android/` matches `app.json`:

   ```
   bun run build:android
   ```

   This deletes `android/`, including `keystore.jks`, `gradle.properties` and the signing change above. Before running it, move the keystore and passwords somewhere outside the project, then copy them back afterwards. Do not use `--clean`, which has the same effect.

3. Re-apply the release signing change in `android/app/build.gradle` (see above).

4. Build the bundle:

   ```
   cd android
   ./gradlew bundleRelease
   ```

   If the build fails with a Kotlin cache error such as `Failed to create MD5 hash`, stop any running build first, then run `./gradlew --stop`, delete `node_modules/@expo/dom-webview/android/build`, and run the build again.

5. The output is at `android/app/build/outputs/bundle/release/app-release.aab`.
   Upload this file in the Play Console.

## Notes

- The Expo `expo-build-properties` configuration pins `android.targetSdkVersion` to **36** (Android 16). Keep this at 36 or higher for Play updates. Existing uploaded bundles do not change when this setting changes; upload a newly built bundle and roll it out to production to resolve the Play notice.
- Before uploading, verify the generated release manifest rather than relying only on `app.json`:

  ```sh
  cd android
  ./gradlew :app:processReleaseMainManifest
  ```

  Check `android/app/build/intermediates/merged_manifest/release/processReleaseMainManifest/AndroidManifest.xml` from the project root: `targetSdkVersion` must be at least `36`, and `versionCode`/`versionName` must match the intended release. The version code must exceed the last code uploaded to Play.
- Debug builds (`npm run android`) still use `debug.keystore`. Only release builds use the upload key.
- Only run one Gradle build at a time. Two at once can corrupt the build cache.
- Steps 2 and 3 are needed after every prebuild. An Expo config plugin would automate them; ask if you want that set up.
